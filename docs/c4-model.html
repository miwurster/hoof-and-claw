Level 1: System context

A Player plays anonymously in a browser. The game server is the only party that observes prices and time; it takes them from Bitstamp's public BTC/USD trade feed.

Level 2: Containers

One Rust process serves the SPA's static files and the API from the same origin and owns the one SQLite file. The API contract is generated from the server's wire types into contract/ (ADR 0014).

Level 3: Components of the game server (Cargo workspace, crates/)

Crates are cut by area of the domain. The cores are synchronous and pure; game is the one async shell; adapters plug into ports the cores own. Arrows follow the allowed crate dependencies, enforced by crate_graph_follows_the_table.

Level 3: Components of the SPA (spa/src/)

One pure reducer takes state plus a server event or user action; one thin hook owns EventSource and fetch. Presentational components receive only props and callbacks (dependency-cruiser rule presentational-components-skip-the-data-layer).

Deployment: production

One Render web service in Frankfurt with a 1 GB persistent disk, behind Cloudflare, within a budget of 10 EUR a month (ADR 0003). GitHub Actions runs only the Green gate; mise run release fast-forwards release, and Render builds the Dockerfile from it (ADR 0013).
